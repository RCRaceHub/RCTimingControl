# User manual

This is the path for a club from nothing to a finished race day, in the order you will meet things. Each step is a few sentences and points to the guide with the detail. Two printable guides come with the app: the **Admin Configuration Guide** and the **Race Meeting Guide**. Open them from the help panel in the app (the **?** button) or at `/print/admin-guide` and `/print/meeting-guide` on the timing laptop, and print them to PDF if you want paper at the track. The full guides, with a menu and search, are also served by the app itself at `/docs` on the laptop's address (the **Docs** link in the sidebar and race control, and on the About page with a QR code). They work without the internet.

RCTC (RC Timing Control) is one program on a laptop at the track. Only officials sign in: admins, race directors and referees. Racers never log in. Their entries come from a RaceHub export file or an RC-Timing CSV, or an official adds them as walk-ins.

## Before race day

### 1. Install it

Put RCTC on the laptop that sits by the decoder. Install it as a background service with the installer for your system: [installing.md](installing.md). To run it from Docker on a laptop or small server instead, see [docker.md](docker.md#running-the-clubs-server-with-docker).

Then open **http://localhost:8080** on the laptop. The About page (`/about`) lists the addresses phones, tablets and boards on the venue network should use. If a phone can't connect, the last part of [First run](installing.md#first-run) covers the firewall and network settings. For a secure (HTTPS) address, which the sound card list on the audio output page needs, see [Secure connection](installing.md#secure-connection-https).

If you want to look around before setting up your own club, [trial-quickstart.md](trial-quickstart.md) loads a demo club with a simulated decoder, and [docker.md](docker.md#try-the-demo) runs the same demo in Docker.

### 2. Run the setup wizard

The first time, a wizard asks for the club profile, a track, a race format, the first staff account and the decoder, then offers an optional network name for the laptop. Everything it asks for can be changed later from the admin panel. The steps are described in the Admin Configuration Guide, section 8 (**First-Run Setup Wizard**).

### 3. Connect the decoder

Under **Admin → Decoder**, enter the decoder's address, leave the protocol on RC4 for firmware below 4.5, and click **Test Connection**, then **Save**. Never connect RCTC and another timing program to the same decoder at once. Setup, hardware notes and troubleshooting are in [decoder.md](decoder.md).

### 4. Set up the club, tracks, formats and officials

- **Club Profile**, **Tracks** (name, length and venue notes) and **Formats** (how a race is run) are in the Admin Configuration Guide, sections 1 to 3. **Scoring Systems** (saved sets of scoring rules that formats and championships pick from) are in [Scoring](scoring.md#6-scoring-systems).
- **Officials** (Admin → Officials) adds the people who sign in, with their roles, sets passwords and disables people who no longer help. Section 7 of the guide covers it, and [installing.md](installing.md#locked-out) covers a club with no admin who can sign in.
- **Competitors** (Admin → Competitors) lists every driver. If the announcer says a name wrongly, click **Say as…** on the driver (admins, race directors and referees can), type how it should sound, click **Play** to hear it in the announcer voice, then **Save**. It stays with the driver for later meetings and imports never change it. Each change is logged with who made it, and admins can see who changed it last. If a driver was entered twice, **Merge…** on the Competitors page lists the likely duplicates and moves one's entries onto the other. **Photo…** adds an optional headshot and up to five driver sponsors (admins and race directors); a car photo is added per entry on the event's Entries tab. See [data-protection.md](data-protection.md) for how pictures are kept and removed. An import is refused, and nothing is saved, when a driver's BRCA number is held by another driver in the same file or by a different competitor already imported from the same system; the message names who holds it, so fix the number at its source and import again. If the number is held by a walk-in or a competitor from another system, the import only warns, because it is usually the same person, and you can merge the two from the Competitors page.
- The classes you can pick for an event come from the club's list of racing classes. Add to that list, and pick a colour for each class, under **Admin → Classes** (admins). The colour shows as a dot beside the class on race control's run order, the line-ups, the live timing heading and the Live race and board views; a class with no colour shows no dot.

### 5. Create the event and bring in the entries

Create the event, add its classes with a format each, and publish it. Then fill it with entries on its **Entries** tab from whichever source you have: a RaceHub Entry Export file, an RC-Timing driver CSV, an entry feed (a web address that serves the file), or walk-ins by hand. If your club uses RaceHub, **Find RaceHub events** on the Events page lists the events the club has released to timing; **Take** creates the event here (if it is new) and sets up its entry feed to fetch from RaceHub. It needs the club's RaceHub key in the settings file and the RaceHub events address, which the dialog asks for the first time. A file you choose yourself shows what will change before anything is saved. An entry feed set to fetch automatically imports changes that apply cleanly on its own, and holds only the revisions that need a decision for you to review. To take a class out of an event, use **Remove** on its row in the event's class list. A class that already has races can't be removed until you delete the event's run order; a class with entries asks you to confirm, and withdraws those entries (they are kept, marked withdrawn) before removing the class. Sections 4 and 5 of the Admin Configuration Guide cover events, classes and every import. `docs/api.md` in the source repository, under "The file format for any booking system", describes the file format a booking system can produce.

### 6. Set up championships

A championship adds up results from several events with a best-X-from-Y rule, a points scale and exclusions. Section 6 of the Admin Configuration Guide covers it, and the help panel on the championship page explains each tab.

## Race types and formats

A class races to a **format**, which you pick in step 4 and again for each class in step 5. The full rules, with the details of how each one starts and ends, are in [race-types.md](race-types.md); how results are ranked is in [scoring.md](scoring.md). In short:

| Format | What it is | Finals |
|---|---|---|
| **Timed** | One timed race per heat, the same start every round | The field is split evenly over the class's finals, no bumping |
| **Bump Up** | Qualifying heats, then finals where the best finishers of each lower final move up into the final above | **Grid size** cars per final, **bump spots** places in each higher final filled from the final below |
| **Shikabane** | Marshal-less racing where a stopped car is out and the lowest points win; optional A, B and C mains with promotion | Mains work like Bump Up finals; see [shikabane-guide.md](shikabane-guide.md) |
| **Points Finals** | Qualifying heats, then finals that each score on their own. Has a **Scoring system** picker in the format editor; pick **BRCA 1/10 off-road** to fill in the BRCA rules ([scoring.md](scoring.md#6-scoring-systems)) | The field is split evenly over the finals, no bumping; or fixed-size finals filled from A, with a 3-leg A final (best 2 count) |

**Balancing the heats.** Select a practice or qualifying heat that has not been called and the **Heat line-ups** panel opens on a **Next heat** tab showing just that heat's line-up. Open the **Move drivers** tab to see who is in each heat of that round. Use **Move to…** beside a driver, or drag the driver onto another heat, to put them there, which is how you even up qualifying once you know who has turned up after practice. The heats don't have to stay the same size (5 and 3 is fine). The selected heat is highlighted. Above the heats, choose whether a move applies to **just this round** or to **every round where both heats are still waiting** (the default), so a qualifying move can cover all the qualifying rounds at once. Practice results are not used to arrange qualifying, and a driver keeps their car number when moved.

**Bump-up finals are fully supported.** To run them, give the class a Bump Up format and set its grid size and bump spots. When you generate the rounds, say how many finals each class has (A, A+B, A+B+C). When the last qualifying heat finishes, press **Calculate finals** in the Finals line-up panel (select any final in the run order). Check **Cars per final**, which starts at the size of a qualifying heat. Once all the qualifying is done, **Calculate finals for all classes** does every class in one go, using each class's default cars per final (classes that are not ready are left alone, and the message says how many). The finals are calculated lowest final first, and you can then move drivers between finals or up and down the grid before the final is called, with the buttons or by dragging: drop a driver on another final to move them, or on another driver to swap places. When a lower final finishes, its best finishers are added to the back of the grid of the final above, and race control shows an alert before you start it. A class without a Bump Up format gets no bumping.

**Shikabane** needs some hands-on work: race control marks every dead car and zombie revival, false starts need the car moved on the track, and the mains and zombie round are run lowest first. [shikabane-guide.md](shikabane-guide.md) lists what is done by hand and in what order.

**How a race starts** is set in the format, separately for heats and finals:

- **Grid**: every car goes together on the start horn.
- **Stagger**: after the horn each driver is called by name every few seconds in grid order, and each car's time starts when it is called. A car that crosses the line before it is called is flagged on the Referee View as a jump start, for the referee to penalise. If full names are too slow, switch on **Say first names only when calling drivers to start** under Audio → Names, and the grid call and these calls use first names.
- **Rolling**: drivers are not called. The clock waits until the first car crosses the line, and then runs for everyone, so every car's time ends together. Race control says "waiting for first car" until then.

**How a race ends**: a timed race ends when every car has taken the flag after the clock runs out. If a car never comes round, the track's max last lap time finishes the race for you. Once the race time is up, race control's cockpit and the Referee View show a red **Closes in** countdown beside the clock: the time left before the race is closed for you, which is the track's max last lap or the format's maximum race window, whichever comes first. A car still on the track when the maximum race window ends the race is marked **DNF** on the results; it keeps its laps and its place. A lap that counts puts the max last lap wait back. **Practice** rounds are run like heats but never score; **open practice** is a separate timing session with no heats or result.

**Qualifying** is ranked by the format's qualifying type. Low points over the best X rounds (**Round by round**) is the one that is fully worked out; the other three types currently rank by total laps and then best lap.

## On the day

### 7. Add a walk-in and swap a transponder

RCTC treats every entrant as present; check-in is RaceHub's. For a driver who did not book, open **Race Control**, choose the event, then **Walk-in**, pick their class and enter them (admins and race directors). Then generate or regenerate rounds so they are in the run order. A class with no confirmed entries is left out of the run order (no heats and no finals), and if no class has any entries, Generate Rounds refuses with a message asking you to add entries or walk-ins first. Add walk-ins before generating: once a race has started the run order can't be regenerated, so a class that was left out stays out. If a driver changes their transponder on the day, open **Race Control**, choose the event, then **Transponders**. Find the entry by name, pick which of its transponders is changing (an entry can have up to four: primary, secondary, third and fourth, and laps from any of them count) and enter the new number; leave it blank to remove a secondary, third or fourth. A walk-in can be given up to four numbers in the same way. When you pick a driver who has raced before, their numbers from their latest entry are filled in for you; change any of them if they have a different transponder today. A swap is logged, and a later RaceHub re-import keeps it. Section 1 of the Race Meeting Guide covers the pre-meeting checks.

### 8. Run the races

Start the event, generate the rounds, then for each race call the grid, start, and finish it. Race control shows live timing, links unknown transponders and handles stops, restarts and bump-ups, and the Referee View raises incidents and applies penalties. The Grid Called panel has a Drivers tab to read the grid from, with a Warm-up column that shows which transponders the decoder has picked up since the grid was called, so a flat or missing one can be sorted out before the start; and a Marshals tab for recording a driver who missed marshal duty. Sections 2 to 7 and 9 of the Race Meeting Guide take you through a race from grid to result. The **Print** link in race control opens the print centre ([screens-and-printouts.md](screens-and-printouts.md#printouts)). Open practice, run when no race is on, is in the help panel on the Practice page. On a practice session, **Say lap times** speaks each lap as the driver completes it, and **First names only** shortens the call; both are per browser and the sound can be sent to its own output in Admin → Audio.

**Finals in legs.** The status bar's **Finals in legs** setting chooses which finals of the event run in legs: **The A final only** (the default, as at nationals) or **Every final**. The number of legs comes from the class's format. It is read when the rounds are generated, so set it before generating them; finals that already exist keep their legs (a final put back by a recalculation follows the setting at that time). Results export sends each leg as its own race. Race directors and admins can change it.

**Reordering the finals.** When a final runs in legs (for example a 3-leg A final), the run order shows small up and down arrows on each final that has not been called yet. Use them to put a leg between other finals, such as leg 1 of the A final between I and H and leg 2 between F and E. A move swaps the final with the one next to it, the legs of one final always stay in order, and a final that has been called or started, or that belongs to a Bump Up class (which always runs in its set order), can't move. Race control, the boards, auto run and the pre-race marshal list all follow the new order. Regenerating the rounds, or calculating the finals again in a way that adds or removes a final, puts the order back to the generated one. Auto run picks up a move on its next tick. Race directors and admins can reorder, and each move is in the audit log. Without a final in legs the arrows do not appear.

To run the races without pressing anything between them, use **Auto run** at the top of the run order in race control. Press **Go** and, each time a race finishes, the next one waits the gap you set (3 minutes unless changed), is called to the grid 30 seconds before it starts, gets the usual start lead-in, and starts. The announcer says the time to the next race at 10, 5, 2 and 1 minutes when the gap is long enough. The countdown to the next start is shown large in the Auto run panel and on the now-and-next pit screen (a hold before the finals shows "Waiting for the finals to be released" there instead of a count). **2 min**, **60s**, **30s** and **10s** bring the next start forward to that long from now, and the **secs** box with **Set** does the same for any time from 0 to 600 seconds (a start is only ever brought forward, never pushed back; this is separate from the gap between races and from how long results stay on screen). **Stop** switches auto run off. By default it holds after the last qualifier so you can calculate and check the finals in the Finals line-up panel, and calculate them again if a result changed; press **Resume** to carry on, or untick the hold to run straight into the finals. It also holds if the next race has no drivers or a command is refused, and says why. When the field is too small to fill every final, calculating the finals removes the unused lowest finals from the run order; if one is kept because something was recorded against it early, auto run steps over it. Auto run only starts when you press **Go**. If you would rather it switched itself on when you start a race by hand, tick "Switch on by itself when a race is started by hand" in the panel (off by default); after the first start the rest then follow without pressing Go, and **Stop** keeps it off until you press Go. A countdown that is already running follows a changed gap too: it ends the new gap after it began, and no sooner than 5 seconds from now. The gap and the two tick boxes are saved on the event as you change them (the gap a moment after you stop typing), so closing and reopening the browser mid-race shows them as you left them. When auto run moves on to the next race, race control stays on the results of the race that just finished for a while, so you can read them: set **Keep results on screen after a race (seconds)** in the Auto run panel (30 by default, 0 to move on at once). It is kept on that browser only, each official sets their own, and the screen moves on early if the next race is already on the grid (if you pick another race yourself, it stays on your pick). Auto run itself is switched off when the app restarts.

**Lap beeps.** Each lap sounds a beep. With pace beeps on (the default), a lap faster than the driver's best sounds an octave higher than the normal beep, and a lap slower than their best sounds an octave lower, so you can hear how a driver is doing without looking. Switch pace beeps off for BRCA events and every lap gets the same plain beep. To use your own sounds instead, upload a faster or slower beep file under Admin → Audio; a pace with no file of its own uses the lap beep.

**Audio templates.** Open **Audio Settings** in race control and use **Templates** to switch the whole set of sounds and calls in one go. Three come ready made: *Club night* (everything on), *BRCA meeting* (plain lap beeps, no running order, no car-by-car finish calls, no stagger calls) and *Practice* (lap beeps only, no horns, no lead-in, no calls). Choose one and press **Apply**. To keep your own, set the sounds and calls as you want them, type a name beside **Save as new** and press the button; **Update** replaces the chosen template with the settings as they are now, and **Delete** removes it. A template holds which sounds and calls are on, the wording, the timings and the lap beep pitch, but not the horn and beep files you uploaded, which stay as they are when you apply one. The same **Templates** bar sits at the top of **Admin → Audio**. That page keeps your changes until you press **Save Settings**, so applying a template there asks first, because it throws away changes you have not saved; and **Save as new** and **Update** ask to save your changes first, since a template copies the saved settings. Race directors and admins can apply and change templates, and each change is in the audit log.

**Sending sounds to different speakers.** Under **Admin → Audio**, **Where each sound plays** lists every sound and call down the side and your outputs across the top. Add an output for each place you want sound, for example *Rostrum* and *Pits and track*, and tick the outputs that play each sound; a sound can go to more than one, and a sound with no ticks is silent (the grid marks it "Plays nowhere"). Removing an output sends a sound that only went there back to race control. Race control's own tab is always an output, and sounds you have not touched play there only. To use another output, click **Open output page** beside it in Chrome or Edge, on the same laptop and in the same browser as race control, click **Choose sound card…** to pick the USB sound card or the speakers (Chrome shows a list of the cards on the page and may first ask to use the microphone, which it needs in order to show their names; the microphone is not recorded), and leave the tab open (the browser only offers sound cards to a page at `http://localhost:PORT` or HTTPS, so on the laptop use the localhost address even if the app runs in Docker; from another address, in Chrome or Edge open `chrome://flags/#unsafely-treat-insecure-origin-as-secure`, add that address, enable it and relaunch); if an output's page is not open when a sound is due, race control plays that sound itself, and the grid shows which output pages are open. An output can also be set to the left speaker only or the right, so one sound card can feed two places. **Test** on each output says its name. The browser only lets audio play after a click on the page, so click **Test** once on each output page after opening it. The routing is kept in that browser, because a sound card belongs to the machine. On another output the spoken lines use the club's Piper voice (the browser's own voice always plays on the default sound card), a long line spoken in pieces; if Piper is not running they play on the default card. Race control's own spoken lines always use the browser voice, so its left or right setting only affects its sounds.

### 9. Show it on screens

Spectator boards and a streaming overlay for OBS need no sign-in: `/boards/now-next`, `/boards/live-race`, `/boards/top` (the live qualifying table), `/boards/view/NAME` (screens you build under Admin, Board views), `/boards/results` and `/boards/overlay` on the laptop's address. An event's sponsors (name and logo) are added on its **Sponsors** tab and show in the overlay's bottom bar; **Admin, Overlay Designer** builds the overlay's address with a live preview and saves looks as named themes (BRCA and Club to start), and a board view can include a **Driver cards** panel with headshots and driver sponsors for the commentator. Section 10 of the Race Meeting Guide lists what each shows and the options for the overlay; [screens-and-printouts.md](screens-and-printouts.md) covers every screen for the pits and OBS and every printout in one place.

### Headshots and car photos without the background

Photos look best on the boards and the streaming overlay with a transparent background. When you add a headshot (Admin → Competitors → **Photo…**) or a car photo (the event's Entries tab → **Car photo**), choose the file and a preview opens with the original on the left. Tick **Remove the background** to see the cut-out on the right (the first one takes a few seconds while the tool loads; after that it is quicker), then **Save without background**. Leave it unticked, or click **Cancel**, to keep the original: nothing is sent to the server until you click Save.

- It runs on the computer you are using, with no internet, so it works at the track.
- The result is a PNG with a see-through background. If it would be over 2 MB it is shrunk to fit; if it still cannot be saved, the original is kept and you are told.
- To add many at once, use **Import headshots…** on the Competitors page, or **Import car photos…** on the event's Entries tab (it works on the class you are viewing). Choose the files, and each is matched to a driver by its file name (`Alex Rowe.jpg`, `alex_rowe.png` and `rowe-alex.jpg` all match Alex Rowe; a trailing number such as `_2` is ignored). A file that matches no one, or two drivers with the same name, is shown as Skipped; pick the driver from its list or leave it skipped. The background is removed from every picture unless you untick the box, and a picture where that fails is saved as the original with a note. A picture that cannot be saved does not stop the rest.
- A RaceHub file or RC-Timing CSV can also name pictures: a headshot address, a car photo address and up to four car colours per entry (CSV columns `Headshot URL`, `Car Photo URL` and `Car Colours`, colours as `#rrggbb` separated by spaces). The import saves the colours at once. When it names pictures, the import window then says how many and offers **Fetch the pictures** (admins only; the laptop needs internet access for it). Tick **Remove the background of each picture** to cut each one out as above, and **Replace pictures already held** to overwrite pictures you or an earlier import added (otherwise they are kept). A driver whose name is not shown in full is skipped, and a picture that cannot be fetched is listed without stopping the rest. Choose **Skip the pictures** to leave them. What a file may contain is in `docs/racehub-expectations.md`.
- It works best on a clear photo of one driver or one car. If it cuts out too much or too little, untick it and save the original, or tidy the picture in an editor first.

## After the race

### 10. Results, corrections and championships

When all races are done, complete the event. Results are on the public pages, printable, and downloadable from the event's page. If a result needs correcting after the finish, the stored result is worked out again and championship points follow. Sections 6 and 8 of the Race Meeting Guide cover finishing, corrections and publishing results. Championship standings update from the saved results and are on the championship's Standings tab and its public page. To give Junior, Vet or F-Grade drivers their own tables as well, set each driver's categories on the Competitors page, then list the categories on the championship's Config tab under Category splits; each split repeats the class tables for those drivers, ranked among themselves.

### 11. Backups

RCTC backs up its database when you complete the event (that closes the race day) and every night, and **Admin → Backups** lists the copies and takes one on demand. The Backups page shows when the last one was taken, and after you close a race day it reminds you for a few days to copy a backup off the laptop. Keep a copy off the laptop: [installing.md](installing.md#copying-backups-off-the-laptop) shows how to use a Dropbox or Drive folder. Restoring is done on the laptop with the service stopped: [installing.md](installing.md#restoring-a-backup).

### 12. Send results back to RaceHub

For events whose entries came from RaceHub, results are queued when a race finishes, when one is corrected and when you complete the event (that closes the day), then sent in the background. The address and key go in the settings file ([installing.md](installing.md#sending-results-to-racehub)), and **Admin → Results to RaceHub** shows what has gone. The file format is in [results-export-v1.md](results-export-v1.md).

### 13. Share a live feed

To let people away from the track follow a race, RCTC can send a live feed to a relay. It is set up in the settings file ([installing.md](installing.md#sending-a-live-feed)) and switched on per event in race control. The format is in [live-feed-v1.md](live-feed-v1.md).
